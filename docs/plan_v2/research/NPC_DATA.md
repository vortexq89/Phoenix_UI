# NPC spawn locations and quest positions — sources, licences, verdict (2026-10-22)

## Short answer
Yes, Phoenix can show quest givers, turn-ins and NPC locations for Midnight without breaking any licence, by combining four sources:

1. **AllTheThings (ATT) database — MIT licence.** Its GitHub repo (`ATTWoWAddon/AllTheThings`) has an MIT `LICENSE` (added 2026-02-16 17:57 Asia/Kuwait, "Copyright (c) 2026 AllTheThings WoW Addon"). Its source DB (`.contrib/.db/standard/…`) gives each quest with `provider = { "n", npcID }` and `coord = { x, y, uiMapID }`.
   Counted in the Midnight zone files (Quel'Thalas folder: Silvermoon, Eversong, Zul'Aman, Harandar, Voidstorm, Isle of Quel'Danas, Coiled Isle):
   - **1,408 quests**
   - **1,938 coordinate entries**
   - **630 quest-giver NPCs with coordinates**
   - 201 standalone NPC entries (rares, vendors)
   
   Earlier expansions are covered the same way. Rules for using it: keep the MIT notice; ship the extracted data in a separate load-on-demand data addon with its own `LICENSE-ATT.txt`; credit ATT on the About page.
   Honest caveat: ATT's CurseForge page still says "All Rights Reserved", but the repo licence is MIT, and the repo is what we would take. Some of ATT's coordinates were contributed by players over the years. ATT asserts MIT over the repo, so the remaining risk is low. If the user wants zero doubt, we can ask the ATT team in their Discord for written confirmation.
2. **Blizzard client data (DB2), generated at build time** like `check_ids` (wago.tools CSV exports, build 12.1.5.70448). This is the same approach EllesmereUI ForeverEssentials uses for its map travel pins.
   - QuestPOIBlob/QuestPOIPoint: 72,740 blobs for 21,809 quests; 16,348 quests have a turn-in polygon (ObjectiveIndex −1); 2,416 quests have ID ≥ 84000 (Midnight era).
   - AreaPOI: 3,946 with positions. TaxiNodes: 1,485 with positions. AreaTrigger: 3,664.
   - UiMapAssignment: converts world positions to map coordinates.
   - Vignette: 7,247 names, but no positions.
   - The Creature table has no positions. **No DB2 has creature spawn points.**
3. **Runtime Blizzard APIs (live, always correct):**
   - `C_QuestLine.GetAvailableQuestLines(uiMapID)` → quest-giver x/y on the map, plus flags (campaign, important, local story…).
   - `C_QuestLog.GetQuestsOnMap`, `C_QuestLog.GetNextWaypoint`, `C_TaskQuest.GetQuestsOnMap`/`GetQuestLocation`.
   - `C_AreaPoiInfo.GetAreaPOIForMap`.
   - `C_VignetteInfo.GetVignettes` + `GetVignettePosition` for live rares and treasures.
   - `C_Navigation` / `C_SuperTrack` for the arrow.
4. **Phoenix community collection (opt-in, later):** records npcID + uiMapID + player x/y on GOSSIP_SHOW / QUEST_DETAIL / QUEST_COMPLETE / vignette sightings.
   - Only when `ns.Secret.IsSecret` is false, out of combat, in the open world.
   - No names, no realm, no GUIDs stored.
   - Uploaded by the Phoenix uploader, aggregated on the Phoenix Cloudflare backend (cluster positions, drop outliers), and published as CC0.
   - Fills gaps ATT does not cover (new patches, hotfixes). Precedents: the Wowhead Client and ATT's own in-game "report missing coordinate" dialog.

## Source-by-source table
| Source | What it has | Licence / terms | Can Phoenix use it? |
|---|---|---|---|
| **AllTheThings repo** | quest → giver NPC + coords + map, rares, vendors, treasures; all expansions incl. Midnight | **MIT** (repo LICENSE, 2026) | **Yes** — extract at build time into the `Phoenix_UI_Data` addon, keep notice |
| wago.tools DB2 exports | Blizzard tables: QuestPOI*, AreaPOI, TaxiNodes, AreaTrigger, UiMap*, Creature names | Blizzard game data; wago.tools has no data licence; we use facts only, generated by script | **Yes** (as already done for IDs) — positions for POIs/turn-ins/flight masters only |
| Runtime Blizzard APIs | live quest givers, waypoints, vignettes, POIs | game API | **Yes** — main source when the player is in the zone |
| Phoenix community data | npc positions from opt-in players | ours → CC0 | **Yes** once the user approves consent text + backend |
| Wowhead (site, Wowhead Client data) | full NPC spawn maps | ToS forbids scraping/automated access and reuse of database content | **No** |
| Questie / QuestieDB | Classic NPC/quest coords | no licence on most of the repo, GPL-3 parts; Classic/Forever only | **No** (and not retail) |
| RareScanner | rare/treasure coords | All rights reserved | **No** |
| HandyNotes plugins (Kemayo's etc.) | treasure/rare pins | mostly ARR or unlicensed | **No** (case by case) |
| TrinityCore / CMaNGOS / AzerothCore DBs | creature spawns (sniffed) | GPL-2; data sniffed from Blizzard servers; old expansions only | **No** for MIT Phoenix; at most a separate GPL add-on — not recommended |
| EllesmereUI ForeverEssentials | Forever map travel pins (from DB2) | ARR | No code; same *method* as ours |
| Addons on I:\ | no NPC coordinates anywhere | — | — |

## Proposed pipeline
1. `tools/build_questdata.py` (new, build time):
   - Sparse-clone ATT (`.contrib/.db/standard/02 - Outdoor Zones`, `01 - Dungeons Raids`).
   - Parse `q(id,{provider,coord,sourceQuests,…})` and `n(id,{coord})`.
   - Join with DB2 QuestPOIBlob/Point for turn-in areas and TaxiNodes/AreaPOI.
   - Emit `Phoenix_UI_Data/QuestData.lua`: per uiMapID, `{questID, giverNpcID, x, y, turnInX, turnInY, prereqs}` packed as strings for memory.
   - Expected size ~2–3 MB for all expansions, ~250 KB Midnight only.
2. `Phoenix_UI_Data` is a load-on-demand addon with its own LICENSE files (MIT for the ATT-derived part).
3. In game, Quests module: runtime APIs first; static data fills in what the APIs don't expose (givers of quests not yet available, NPC locations, prerequisites).
4. Later: the community collector updates the data between ATT releases.
