# Phoenix UI: full review, 2026-10-27

Branch `feat/review`, stacked on `feat/deferred-d` (PR #47, closed but still the code under review). Read-only review: the only code changes are the two trivial fixes listed in section 9. Checked by reading the code and by loading every addon in the offline harness (`.tools/harness`, retail and Forever flavours). Doc claims were not taken as proof.

## 1. Verdict

**No, the plan is not complete end to end.** The core (kernel, schema, live apply, Studio, Options, 30 modules, Sentinel, Companion, Forever slice) is built and tested offline, and the decided defaults are set correctly. What is left:

- an EllesmereUI-parity layer (global Fonts/Colours/Glows pages, free text slots, raid pets/party targets/extra frames, nameplate class power, Grid Mode)
- the rest of the media library
- a few UX gaps
- **all in-game verification**: nothing has been run in the game yet, and `docs/INGAME_CHECKS.md` lists 46 check groups

Two items that were marked "blocked" are actually buildable on 12.1.5 (see section 10): **private-aura sounds** and **enemy range fade**.

## 2. Method

- **Harness audit.** I wrote an audit script that loads Core and all 32 children through `wow_stub.lua` and dumps four things: every schema key (owner, type, mode, apply, default, page, label, tooltip), every module (default state, load condition), every preview and the sidebar layout.
- **Owner checks.** Every §1.O owner row and every M/P row in §13 and §15.3 was checked by searching the code for its owner symbol or setting key, then opening the matching file.
- **TOC checks.** A script parsed all 33 TOC files: duplicate entries, unlisted `.lua` files, Interface lines and dependencies.
- **Tests.** `/pui test` ran in both flavours, plus guardrails, luacheck and locales.
- **Limits.** The 374-row parity tables (`EllesmereUI_parity.md`, `AllAddons_parity.md`) were not proven row by row. I checked them through §13 and §15.3, which summarise them (see section 5). The mockups were compared screen by screen as structure (screen exists, preview exists, controls exist), not as pixels, because the harness has no renderer.

## 9. Trivial fixes made in this branch

1. **Nav (Phoenix_UI_Options/Nav.lua).** Arena, Pulse, Spark, CastHistory, PvP, RaidTools, Friends, Forever and QoL had no sidebar entry. They fell into "Interface" with a generic icon, raw names ("CastHistory", "QoL") and no description. Each now has its icon, label and description and sits in the right group: Combat, Group, Social & Chat or Tools.
2. **Diagnostics page (Phoenix_UI_Options/DiagPage.lua).** All its keys are Advanced, so the page disappeared in Simple mode. It is now a virtual page, like Blizzard and Ledger.

Tests: 403/403 pass in retail and Forever, and the harness checks are OK.

## 10. Workarounds for blocked and restricted items

Feasibility key:

- **taint-safe**: no writes to Blizzard-owned frames or their tables; hooks are `hooksecurefunc` post-hooks; protected work goes through CombatQueue.
- **secret-safe**: possibly-secret values only go to widgets (`SetValue`, `SetText`, `SetAlphaFromBoolean`, `SetVertexColorFromBoolean`, duration objects). They are never compared or used in arithmetic.

1. **W1 private-aura sounds:** it is not blocked; build it with `C_UnitAuras.AddAuraSound`.
