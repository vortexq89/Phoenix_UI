# Plugin split (t161 B) - spec

Status: spec only, not built. Owner ask (t161u): EllesmereUI-style split, each settings system its own load-on-demand
addon folder `Phoenix_UI_<System>`, chosen in a plugin manager, loaded only when enabled; install and package them all.

## 1. Today
`Phoenix_UI` (core + 30 modules in `Modules/`), `Phoenix_UI_Options` (settings, LoadOnDemand),
`Phoenix_UI_Data` (quest data, LoadOnDemand). Every module is already a toggleable plugin (`ns:NewModule`, live on/off),
but all module code is loaded at login.

## 2. Target layout
* `Phoenix_UI` keeps Core/, UI/, Libs/, Locales/, Media/ and the always-needed systems: General, Movers, Bugs,
  Quality, Profiles (the plugin manager lives here).
* One folder per system, `## LoadOnDemand: 1`, `## Dependencies: Phoenix_UI`, both TOC flavours generated by
  `tools/gen_tocs.py`:
  ActionBars, UnitFrames, GroupFrames, NamePlates, CastBars, Auras, Tracker (Cooldown Manager), CooldownText,
  CombatText, DamageMeter, SpellHistory, Chat, Minimap, Tooltip, Bags, ItemLevel, DataTexts, Skins, Automation, AFK,
  MythicPlus, Encounters, PvP, Sim, Quests, GroupFinder (26 plugins).
* Each plugin folder holds that system's module files moved unchanged from `Modules/<System>/`; its options page stays
  in `Phoenix_UI_Options` (the settings window already loads on demand) so pages exist even for plugins not loaded.
* Shared namespace: the core exposes `PhoenixUI_API = ns` once at load (the only new global, added to .luacheckrc);
  a plugin's first file is `local ns = PhoenixUI_API` so module code keeps using `ns` unchanged.

## 3. Loading
* At `ADDON_LOADED` of Phoenix_UI, for every module the profile has enabled, `C_AddOns.LoadAddOn("Phoenix_UI_<X>")`
  before `ns:InitializeModules()`; flavour gating (`ns:Supports`) and `loadWhen` stay as they are.
* Enabling a plugin at runtime loads its addon and enables the module live (LoadAddOn is allowed out of combat;
  deferred with `ns.Combat:Run`). Disabling is live; the code stays resident until the next /reload (WoW cannot
  unload addon code), and the manager says so.
* Missing folder (partial install): the manager shows "Not installed" and the module stays off; no errors.

## 4. Plugin manager (Phoenix > Plugins page, v4 Flow)
Cards per category (Bars, Frames, Interface, Combat, Content, Phoenix) with: icon, name, one-line description, state
chip (Loaded / Off / Not installed / Needs reload), memory after load (`GetAddOnMemoryUsage`), toggle. Header: counts,
"Enable all", "Minimal" preset (core + bars + frames), search. Same data as the module list today.

## 5. Install, package, CI
* `tools/pui_sync.ps1`: robocopy every `Phoenix_UI*` folder from the repo (core excludes stay); removes nothing it did
  not create.
* `.pkgmeta`: `move-folders` for every plugin, so the CurseForge/Wago zip ships all folders.
* `check_api.py`: TOC chain per folder; harness loads core + all plugins in order and also core alone.
* Migration: no saved-variable change (module settings stay under `PhoenixUIDB`).

## 6. Steps (one commit and push each)
1. API global + loader + manager page, still with modules in core (no behaviour change).
2. Move systems in batches of ~5 folders, harness + both flavours green per batch.
3. Installer, .pkgmeta, docs, CHANGES.
